حزمة مراجعة: فصل المشتريات عن الإيجارات
المشروع: AJRNI | تاريخ التجميع: 2026-11-02
نطاق الفحص: قراءة ملفات المشروع فقط. لم تُعدّل ملفات الشيفرة أو قاعدة البيانات، ولم تُشغّل استعلامات DB. لا يحتوي التقرير كلمات مرور أو بيانات عملاء شخصية.

ملاحظات عن نسخة العمل
- api/get_customer_orders.php معدل محليًا؛ هذا التقرير يصف محتواه الحالي.
- لم يتوفر ملف SQL للمخطط ولم تُنفذ SHOW COLUMNS. الأعمدة أدناه مستنتجة من SQL وليست تأكيدًا للمخطط الحي.
- البحث عن rental_products لم يجد له جدولًا مستخدمًا أو ملفًا في المشروع.

1. مسار البيانات الحالي

المنتجات: seller_dashboard.php يضيف المنتج إلى products ويربطه بالبائع بواسطة seller_id = $_SESSION['user_id']. حقول الإضافة الظاهرة: name, category, price, image, description, is_featured. مبلغ التأمين يضمّن في description كنص، ولا يضاف كعمود منفصل.

الإيجار: prodcuts.html يحسب السعر بحسب الأيام ويضيف التأمين، ثم يحفظ محليًا في localStorage.cart عنصرًا فيه type وstartDate وendDate وdays وdeposit. cart.html يعرض هذه البيانات ويرسل cart كاملة إلى api/checkout.php.

الحفظ: checkout.php يقرأ عناصر cart لحساب المجاميع، لكنه ينفذ INSERT واحدًا في orders ولا يحفظ عناصر cart أو product_id أو type أو startDate/endDate أو days أو deposit في صف الطلب.

العرض: prodcuts.html يستدعي api/get_customer_orders.php ثم يصنف كل سجل حسب start_date وend_date: غيابهما يعني شراء، ووجودهما يعني إيجار. لا يمرر مسار checkout الظاهر هذين التاريخين إلى INSERT؛ لذلك لا يملك هذا المسار حاليًا بيانات تمييز الإيجار المطلوبة للواجهة. user-drawer.js يضع كل نتائج الطلبات في حاوية الإيجارات ولا يملأ حاوية المشتريات.

3. أسماء الجداول والحقول والعلاقات المستدل عليها

products
- الحقول التي تشير إليها الاستعلامات: id, seller_id, name, category, price, image, description, is_featured. admin.php يشير أيضًا إلى status.
- العلاقة المستدل عليها: products.seller_id -> users.id.
- التأمين ليس عمودًا في INSERT الظاهر؛ يوضع داخل description.

orders
- INSERT يشير إلى: user_id, subtotal, shipping_fee, total_amount, shipping_method, payment_method, status.
- الاستخدام يشير أيضًا إلى id وcreated_at. الواجهة تتوقع start_date وend_date.
- العلاقة المستدل عليها: orders.user_id -> users.id.
- checkout لا يكتب product_id ولا تفاصيل العناصر. وجود created_at أو start_date/end_date فعليًا غير مؤكد.

users
- الحقول المستخدمة في الروابط: id وfull_name؛ تسجيل الدخول يستخدم email وrole كذلك.
- العلاقات المستعملة: orders.user_id = users.id، وproducts.seller_id = users.id.

rental_products
- لم يظهر أي مرجع له في الملفات أو SQL؛ لا يمكن إثبات وجود الجدول أو أعمدته.
- لم يظهر جدول order_items أو جدول تفاصيل طلب بديل ضمن المسارات المفحوصة.

4. ما تثبته الأدلة وما لا تثبته

مؤكد من الشيفرة:
1) checkout لا يخزن تواريخ الإيجار أو تفاصيل العناصر في INSERT الظاهر.
2) واجهة فصل التبويبين تعتمد على start_date/end_date.
3) user-drawer.js يضع الطلبات في حاوية الإيجارات ولا يعرض قائمة مشتريات.
4) مسار تحميل المنتجات api/get-products.php غير موجود ضمن الملفات المفهرسة؛ وget_prodcuts.php يحوي علامات دمج.
5) لم يُعثر على استخدام rental_products.

يحتاج قاعدة البيانات/الخادم لتأكيده:
- وجود الأعمدة created_at وstart_date/end_date وproduct_id فعليًا في orders.
- وجود triggers أو كود خارج مساحة المشروع يحفظ تفاصيل إضافية.
- مطابقة نسخة الخادم للملفات المحلية.

5. استعلامات قراءة فقط للتحقق لاحقًا
لم تُنفذ هذه الاستعلامات:
  SHOW TABLES;
  SHOW COLUMNS FROM products;
  SHOW COLUMNS FROM orders;
  SHOW COLUMNS FROM users;

بعد التحقق من الأعمدة الموجودة فقط، يمكن فحص طلبات المستخدم دون بيانات شخصية:
  SELECT id, user_id, status, subtotal, shipping_fee, total_amount, created_at
  FROM orders WHERE user_id = 22 ORDER BY id DESC;
احذف من SELECT أي عمود لا يظهر في SHOW COLUMNS. لا تستخرج الاسم أو البريد أو بيانات الدفع.
